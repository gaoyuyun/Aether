# 用户 API Key 访问限制

用户管理和“我的 API Key”中，提供商、端点、模型分别支持“允许”和“拒绝”，也可以跟随用户权限。Key 的限制始终受用户及用户组权限约束。

| 配置 | 含义 |
| --- | --- |
| 跟随用户 | 当前维度不额外限制 |
| 允许并选择项目 | 仅允许所选项目 |
| 允许列表为空 | 全部禁用 |
| 拒绝并选择项目 | 排除所选项目，新增资源仍按用户权限开放 |
| 拒绝列表为空 | 不排除任何项目 |

API 保留 `allowed_providers`、`allowed_api_formats`、`allowed_models`，新增对应的 `denied_*` 字段，取值为字符串数组或 `null`。更新时省略字段表示保持原值；提交一个非空或空数组会切换到该列表的模式，并清除同维度的另一列表。一个请求不能同时为同一维度提交两个数组。跟随用户时将同维度两个字段均设为 `null`。

端点限制针对 API 格式（例如 `openai:responses`），沿用现有格式别名和伴随端点的权限规则。模型限制针对全局模型名称；请求中的模型别名和模型指令不能绕过拒绝规则。

删除提供商、最后一个对应格式的端点或全局模型后，关联的允许和拒绝列表会自动清理；修改端点格式、全局模型名称也会清理旧引用。共享同一种格式的其他端点仍存在时保留该格式。暂时停用资源不会删除限制。历史遗留引用会在管理端或用户端读取 Key 列表、用户读取 Key 详情时补清理并持久化，不需要手动保存。

清理保留空数组的语义，使用比较后更新避免覆盖并发编辑。目录读取失败或对应目录不可用时不会把已有选择清空。前端在打开弹窗、上游目录变更和窗口恢复焦点时重新加载，并完整加载模型分页后才清理选择。

数据库迁移 `20260911010000_add_api_key_denylists` 为 PostgreSQL、MySQL、SQLite 添加三个可空列。旧 Key 的行为保持不变；部署时需按现有流程执行数据库迁移。用户导出、导入与回滚包含拒绝列表。
