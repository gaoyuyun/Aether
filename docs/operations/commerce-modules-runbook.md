# 商业模块维护手册

本文适用于钱包和套餐软模块开关：

- `module.wallet.enabled`
- `module.billing_plans.enabled`

这些开关控制运行时鉴权、套餐额度和钱包结算，不会卸载 repository，也不会移除数据库表。

## 支持的运行方式

本 fork 的默认运维边界是个人或小范围单节点部署，尤其是 SQLite Single Node。商业模块切换属于维护操作，不保证活动流量下的即时强一致热切换。

系统配置使用 30 秒本地缓存，auth context 最长缓存 60 秒。配置通过当前实例的管理接口写入时会主动刷新相关本地缓存，但不同实例之间没有商业模块专用的即时失效协议。

## 标准切换流程

1. 停止外部入口流量，不再接受新的 AI 请求。
2. 等待所有在途请求结束，确认 usage worker 和结算队列没有待处理请求。
3. 通过管理界面或管理 API 修改钱包、套餐开关。若服务器已经完全停止，也可以在备份后直接修改数据库配置。
4. 重启应用。多实例部署必须重启全部应用实例。
5. 确认公开模块状态和管理页面显示符合预期，再恢复入口流量。

重启会清空进程内配置、鉴权和 dashboard 缓存，因此是推荐且最容易验证的切换边界。

## 不重启时

如果单节点部署明确选择不重启，必须继续保持业务流量停止至少 60 秒，再检查模块状态并恢复流量。该等待时间覆盖 30 秒系统配置缓存和最长 60 秒 auth context 缓存。

不要在等待期间发送用于真实计费的探测请求。模块状态检查应使用公开状态接口或管理页面。

## 一致性边界

- 维护窗口开始前已经启动的请求可能继续使用其开始时的商业策略，并按 usage metadata 中的策略完成结算。
- 重启完成后启动的新请求使用数据库中的当前开关值。
- 活动流量下切换、多实例只重启部分副本、直接修改数据库但不重启或等待，均不属于支持的操作方式。
- 如果未来需要零停机热切换，应重新引入跨实例版本或失效机制，并增加相应的并发和端到端测试。

## 升级与备份

升级迁移会保留旧安装原有的计费启用行为；全新安装默认关闭钱包和套餐。执行升级或直接修改配置前，应备份 SQLite 文件或服务端数据库。
